SQL (Relational) vs. NoSQL (Non-Relational)

Choosing the right database is a critical decision in system design.

SQL Databases

Examples: MySQL, PostgreSQL, Oracle

  • Structure: Data is stored in tables with a predefined schema.
  • Transactions: Provide ACID (Atomicity, Consistency, Isolation, Durability) guarantees.
  • Use Cases: Applications that require strong consistency and complex transactions, such as e-commerce and financial systems.

NoSQL Databases

Examples: MongoDB (Document), Cassandra (Wide-column), Redis (Key-value)

  • Structure: Flexible schema. Can be document-oriented, key-value, wide-column, or graph-based.
  • Scalability: Generally scale out horizontally more easily than SQL databases.
  • Use Cases: Big data, real-time applications, and applications with unstructured or semi-structured data.

Database Scaling Techniques

  • Replication: Creating copies of the database. A common setup is a primary-replica relationship, where writes go to the primary and reads are distributed among the replicas. This improves read performance and provides redundancy.
  • Sharding (Data Partitioning): Splitting a large database into smaller, more manageable pieces called shards. Each shard has the same schema but holds a different subset of the data. This allows for horizontal scaling of both reads and writes.
  • Indexing: Creating data structures (indexes) that improve the speed of data retrieval operations on a database table. Indexes are used to quickly locate data without having to search every row in a database table every time a table is accessed.
